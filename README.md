# Naval Gazette Notes

[![検査](https://github.com/cpsbvbng26-dotcom/naval-gazette-notes/actions/workflows/verify.yml/badge.svg)](https://github.com/cpsbvbng26-dotcom/naval-gazette-notes/actions/workflows/verify.yml)

海軍公報から一件ずつ史料を翻刻し、その史料で確定できることと、できないことを分けて
記録する。

いまのところ一件である。1943年9月11日発令の叙勲名簿から、瑞寶章四等の受章者 10 名。

## 史料ノート

**[A Naval Gazette Entry for Lieutenant Otani Tsune（大谷恒）](pdf/naval-gazette-entry-otani-tsune.pdf)**
*A Note on the Investiture List of 11 September 1943 in the Naval Gazette (Internal Circulation Only), Extra Edition*

根本卓哉 — 2026年8月 — プレプリント（査読前）
DOI [10.5281/zenodo.22055709](https://doi.org/10.5281/zenodo.22055709)
Knowledge Commons [レコード](https://works.hcommons.org/records/q36z2-98e12) —— 同じ史料ノートの別の所在。**引用は Zenodo の DOI を正とする。**

海軍の下級・中級士官は、自分についての伝記的な記録をほとんど残しない。この階層の人物についての情報は、
散在する公報の記載に頼ることになる。この史料ノートが扱うのは、そのうちの一件である。

**確定できること** —— 発令時の階級は海軍大尉、叙勲は瑞寶章四等、発令日は1943年9月11日、假記番号は 2603-25。

**確定できないこと** —— 名前の読み（大谷はオオタニともオオヤとも、恒はツネともヒサシとも読める）、
所属や乗艦、生没年、そして生前叙勲か死後叙勲か。

史料ノートは後者を**明示的に列挙**する。「オオタニ・ツネ」という表記も、便宜上のものだと断ったうえで使っている。

### 「大尉」と書いてあることの意味

**この史料が確定させるのは、1943年9月11日**時点**の階級である。** その後の階級については、
この文書は何も言わない。したがって、別の資料や家伝が少佐その他の階級を伝えていても、
**それ自体はここでの大尉と矛盾しない。** 昇進、あるいは死後の特進を、この一件は排除しないからである。

排除もしなければ、裏づけもしない。**この名簿から言えるのは発令時点のことだけである。**
最終階級を確定するには、別の史料（辞令公報、履歴原表など）が要る。

なお、大谷の行に `故`（故人を示す接頭辞）はない。史料ノートはこれを生前叙勲を示唆する材料として
挙げつつ、一件だけでは慣行を確定できないとして結論を出していない。

## データ

史料ノートの第3節にある翻刻を、そのまま機械可読な形にしたものである。

| | |
| --- | --- |
| [`data/investiture-1943-09-11.csv`](data/investiture-1943-09-11.csv) | 10件。表計算ソフトでそのまま開ける |
| [`data/investiture-1943-09-11.json`](data/investiture-1943-09-11.json) | 同じ内容に、出典と凡例を付けたもの |
| [`data/README.md`](data/README.md) | 各列の定義と、記録しなかったもの |
| [`data/check.py`](data/check.py) | 二つのファイルの整合と、階級の連鎖を確かめる |

**なぜデータにするのか。** 史料ノートの第7節は、次の一手として「同じ発令の他の受章者を比較し、名簿の編成原理を
再構成すること」を挙げている。**それには翻刻が表になっている必要がある。** PDF の中にあるままでは、
誰も着手できない。

### 「同」をどう扱ったか

原文の階級欄は、最初の一件に `海軍大尉` と書き、以降は `同` で繰り返す。データでは階級を各行に展開し、
**それが書かれていたものか、繰り返しから引き継いだものかを `rank_source` 列で区別**している。

```
2603-18  printed  海軍大尉   ← 書かれている
2603-19  ditto    海軍大尉   ← 同 から引き継いだ
```

史料ノートが大谷の階級を大尉と断定できる根拠は、まさにこの連鎖である（2603-18 に `海軍大尉` とあり、
間の各行がすべて `同` なので、2603-25 まで引き継がれる）。**根拠を列として残すことで、
読者が同じ推論を辿り直せる。**

### データを確かめる

```
python3 data/check.py
```

標準ライブラリだけで動く。**GitHub Actions が push ごとに実行している。**
21 項目を確かめる —— CSV と JSON が全列で一致すること、
假記番号が 2603-18 から欠けなく並ぶこと、`同` の連鎖が破れていないこと（引き継ぐ元のない `ditto` は
翻刻の取りこぼしを意味する）、**史料ノート第4節(1) の推論をデータの上で実際に辿り直し、
2603-25 の階級が海軍大尉に行き着くこと**、**出典表記が四箇所で一字一句同じであること**、そして**原資料の画像が混入していないこと**。

## 出典

**この一文が、このリポジトリの正式な出典表記である。** 以下すべての場所で同一の文字列を用いている。

```
JACAR（アジア歴史資料センター）Ref.C12070491000、海軍公報（部内限）號外　昭和十八年九月十一日發令（防衛省防衛研究所）
```

レコードの恒久リンク: <https://www.jacar.archives.go.jp/das/meta/C12070491000>

アジア歴史資料センターは出典表記の形式を定めている —— レファレンスコードは `Ref.` を冠した11桁、
原資料の所在は**簿冊レベルまでの資料名と所蔵機関名**を添える、二回目以降は `JACAR` と Ref. を略記してよい。
上の一文はこの形式に合わせたものである。**このリポジトリのデータを再利用する場合も、
自己流に書き換えず、この形のまま引くこと。**

> **未確認が一点ある。** 上の表記には**簿冊名と整理番号が入っていない。**
> 規定は簿冊レベルまでの記載を求めているが、JACAR の書誌からまだ確認できていない
> （この作業環境からは jacar.go.jp / jacar.archives.go.jp に接続できない）。
> 確認でき次第、件名と所蔵機関名のあいだに補う。

翻刻は、JACAR が公開する画像を目視で確認したものである。印刷の状態により複数の読みが成り立つ場合は、
その旨が史料ノート本文に示されている。

### 一箇所で決めて、機械で揃えている

同じ出典を README・JSON・`CITATION.cff` の三箇所に書くと、片方だけ直したときに食い違う。
そうならないよう、[`data/check.py`](data/check.py) が**三箇所の文字列が一字一句同じであることを確かめる。**
ずれた時点で検査が落ちる。

## 原資料の画像は入っていない

**このリポジトリにあるのは、テキストの翻刻と、著者自身の史料ノート PDF だけである。**
`pdf/` の 1 ファイルは wkhtmltopdf で組んだ全2ページの自作 PDF で、**埋め込み画像は 0 件**。
JACAR が公開する原資料のスキャン画像は、どこにも含めていない。

これは意識して引いた線である。JACAR の案内では、**防衛省防衛研究所提供資料の資料画像**を
出版物や番組に用いる場合、所蔵機関への照会が求められる。翻刻テキストと自作の史料ノートは
それに当たらないが、**画像を入れた時点で話が変わる。**

> **今後の運用。** このリポジトリに原資料のスキャン画像を加える場合は、
> **その前に防衛省防衛研究所 戦史研究センターに確認すること。**
> 忘れないよう、[`data/check.py`](data/check.py) が画像ファイルの混入と、
> PDF への画像埋め込みを検査する。**入った時点で検査が落ちる。**

著作権法上の評価をここで下すつもりはない。**運用上の線だけを引いて、機械で守っている。**

## 収録していないもの

**同じ公報にあるが、翻刻していない部分がある。**

- **敍勲三等授瑞寶章**（假記 2603-13 〜 2603-17、5名）。史料ノートは五名の受章者がいることを記録しているが、
  氏名は翻刻していない
- 同じ画像の罫線の下から始まる **2603-30 以降の一群**。これは別項目にあたるため、史料ノートは扱っていない

**読みは一切記録していない。** 公報に振り仮名がないためである。推測で補うと、
史料にない情報を史料から出たもののように見せることになる。

## AI の利用

[![Built with Claude Code](https://img.shields.io/badge/Built%20with-Claude%20Code-D97757?style=for-the-badge)](https://claude.com/claude-code)

史料ノートについて。構成の立案と散文の編集に Claude（Anthropic）を用いた。史料の選択、
翻刻の検証、論旨に関わる判断はすべて著者が行い、責任も著者にある。詳細は史料ノート末尾の
開示文にある。

英訳について。史料に書かれている内容の英訳は、言語モデル（ChatGPT / OpenAI）が行った。
解釈も補足も含まない。PDF の開示文にこの記載は無い。紙面は Claude による構成と推敲しか
述べていない。凍結された PDF は直せないので、[ERRATA.md](ERRATA.md) の `E3` に記録した。
当時、自己登録のプレプリントに開示義務は無く、規則違反ではない。

**このリポジトリについて。** README、`CITATION.cff`、データファイル、および `data/check.py` は
Claude Code（Anthropic）を用いて作成し、実行した。**データの内容は史料ノート第3節の翻刻そのもの**で、
新たな読み取りは加えていない。`rank_source` 列による「同」の解決は、史料ノート第4節(1) の論証を
そのまま列にしたものである。検査スクリプトが報告する結果は、実行して得たものである。
